# What the live tester found, why the harness did not, and the test complex that replaces it

Written 2026-08-14 after GrafCiel's session of 2026-08-13, 15:00–18:20 MSK, on the test server
(`/home/user/milky/eturlia_new/server`, port 25963, build `2026-08-13T11:46:07Z`).

Everything below is taken from the server's own logs, not from the report.

---

## 1. What actually happened, by evidence

### 1.1 Thirty-three boots that never reached the world (15:39–15:52)

`logs/2026-08-13-{9..41}.log.gz` are 33 consecutive runs of about eight seconds each, every one
ending on:

```
[Eturlia] WARN Main: Failed to load datapacks, can't proceed with server load.
Missing data pack create:dynamic_data
Missing data pack mod/starcatcher:built_in_datapacks/selling_bin_fishes
Missing data pack mod/starcatcher:built_in_datapacks/selling_bin_starcatcher_emeralds
Missing data pack supplementaries:generated_pack
Missing data pack ibo
```

A supervisor restarted the server every ~22 s, so the tester saw "the core dies within a minute"
and `Server closed`. The first boot that survived is `2026-08-13-8.log.gz` at 15:53 — which is the
run whose `Done (12.673s)` was quoted as the project's headline number. The 33 failures immediately
before it were never looked at.

The missing-pack lines are only what the run printed on its way down. The abort itself comes from
the dimension registry, and `logs/eturlia-noise.log` holds the cause:

```
java.util.concurrent.ExecutionException: java.lang.IllegalStateException:
  No key preset in MapLike[{biomes:[{biome:"minecraft:nether_wastes",parameters:{...}}]}]
  at com.mojang.serialization.DataResult$Error.getOrThrow(DataResult.java:287)
```

A multi-noise biome source written in the inline `biomes:` form is being decoded by the branch that
demands `preset:`. `MultiNoiseBiomeSource`'s codec accepts either shape; here the either-codec
picked the wrong branch and reported the first branch's error, so the world's Nether could not be
built and `Main` refused to start. It is the same family as the `Failed to parse either. First: No
key amount in MapLike[...]` lines the noise log carries elsewhere.

Two things follow. The failure is in a codec, not in a mod's data — so it belongs in the core. And a
world that has been played on can stop booting permanently, with the console showing only a list of
packs that look unrelated. Nothing in the harness looked at a second boot of the same world, which
is why T1 in §3 exists.

### 1.2 A modded projectile stops the whole server (16:33, and repeatedly)

```
ClassCastException: class org.bukkit.craftbukkit.entity.CraftEntity$EturliaUnknownEntity
                    cannot be cast to class org.bukkit.entity.Projectile
  at org.bukkit.craftbukkit.event.CraftEventFactory.callProjectileCollideEvent(CraftEventFactory.java:1473)
  at org.bukkit.craftbukkit.event.CraftEventFactory.callProjectileHitEvent(CraftEventFactory.java:1516)
  at net.minecraft.world.entity.projectile.Projectile.preHitTargetOrDeflectSelf(Projectile.java:229)
  at net.minecraft.world.entity.projectile.AbstractHurtingProjectile.tick(AbstractHurtingProjectile.java:94)
  ...
  at io.papermc.paper.threadedregions.TickRegions$ConcreteRegionTickHandle.tickRegion
```

and, on the same tick:

```
ClassCastException: class org.bukkit.craftbukkit.entity.CraftLivingEntity cannot be cast to
                    class org.bukkit.entity.Slime
ERROR TickRegionScheduler: Region #20 centered at chunk [-23, 34] in world 'world' failed to tick
```
→ `Stopping server`.

This is our own compatibility plane failing. Modded entities are wrapped in a single generic
`CraftEntity$EturliaUnknownEntity` so that `getType()` can answer `UNKNOWN`. The wrapper satisfies
`getType()` and breaks everything else: vanilla CraftBukkit code casts the Bukkit handle to
`Projectile`, `Vehicle`, `Slime` and so on. A failed cast throws inside the entity tick, Folia
treats a region tick failure as fatal, and the server shuts down.

The tester's sentence "I click the potato cannon and it immediately says Server closed" is this
line. So is "the barrel did not disappear and now it will not let me in".

### 1.3 Every modded GUI is dead

```
AbstractMethodError: Missing implementation of resolved method
  'abstract org.bukkit.inventory.InventoryView getBukkitView()'
  of abstract class net.minecraft.world.inventory.AbstractContainerMenu
```

CraftBukkit adds an abstract `getBukkitView()` to `AbstractContainerMenu`. Mod menus are compiled
against vanilla, do not implement it, and throw the moment the menu is opened. "Backpacks do not
open at all", "the soul altar either places items or they vanish".

### 1.4 Mixins that do not apply, silently

In the last boot alone:

```
InvalidInjectionException  Invalid descriptor on wover.core.mixins.common.json:registry.RegistryDataLoaderMixin
InvalidInjectionException  Invalid descriptor on bclib.mixins.common.json:BoneMealItemMixin
InvalidInjectionException  Invalid descriptor on immersive_melodies.mixins.json:ServerWorldMixin
InvalidMixinException      @Shadow method respawnDragon in betterend.mixins.common.json:EndDragonFightMixin
                           was not located in the target class
InvalidAccessorException   No candidates were found matching entityMap:Lit/unimi/dsi/fastutil/ints/Int2ObjectMap;
                           in net/minecraft/server/level/ChunkMap  (emotecraft)
Critical injection failure: LVT in SpreadingSnowyDirtBlock::randomTick
```

and at runtime, 352 times:

```
ClassCastException: class net.minecraft.world.level.levelgen.NoiseBasedChunkGenerator
                    cannot be cast to class dev.worldgen.lithostitched.mixin.common.ChunkGeneratorAccessor
```

Paper rewrites these methods, so the mods' injection points no longer match. Our error handler
turns the failure into a log line and lets the boot continue. The mod then loads *without the half
that does the work*: BetterEnd's biome source is never installed (structures generate, biomes do
not — exactly what the tester saw in the End), lithostitched's worldgen modifiers never run.

Leniency is right; leniency **without a manifest** is what made this invisible.

### 1.5 A guard plugin of our own made the session unplayable

`plugins/FarCoordGuard/config.yml`, written 2026-08-12:

```yaml
max-abs-xz: 4500.0
clamp-on-move: true
safe-spawn: {world: world, x: 0.5, y: 80.0, z: 0.5}
deny-message: "§cКоординаты слишком далеко — возврат в безопасную зону (защита от краша чанков)."
```

It applies to every world, so past ±4500 in any dimension the player is yanked to the overworld
spawn on every move. The tester spent 10 minutes fighting it. It is test-rig furniture, not the
core, and it has to be scoped or removed before any further session.

### 1.6 Still unexplained, needs reproduction

- `Internal Exception: io.netty.handler.codec.DecoderException: Failed to decode packet
  'clientbound/minecraft:set_entity_data'` — client side, so the server log cannot show it. Two
  triggers reported: a Let's Do Vinery barrel and Create's potato cannon.
- Twilight Forest: the client hangs on the loading screen. The server logs no dimension change at
  all for the tester, so the client never got a usable dimension-change packet.
- Placing a modded block makes every subsequent placement vanish until a relog.

All three are packet-level, all three need a real client to observe. See §3.

## 2. Why the existing harness could not have caught any of it

| What was tested | What it actually proved | The gap the tester walked into |
|---|---|---|
| `logcheck.py` / `finalscan.py` boot grade | the *console* had 2 alarming lines | every third-party stack trace is routed to `logs/eturlia-noise.log`, which nothing ever read. The grade measured the filter, not the server |
| `headless-smoke-empty` in CI | the jar boots **a fresh empty world** | the failure in §1.1 only exists on a world that has been played on, because it is the saved pack list that goes stale |
| static binding scan | no final-override or abstract-method conflicts | `getBukkitView()` is an *added abstract method*: the class binds, and only throws when a menu is opened |
| `cmdtree.py`, command-feedback markers | commands are registered and answer | nothing a command can answer touches entity ticking, menus, or packet encoding |
| headless client `clienttest3.sh` | a modded client can join and stay | the client joined, stood at spawn and was asserted on chat text. It never placed a block, opened a GUI, fired a projectile or changed dimension |
| Create/Aeronautics scenarios | contraptions assemble and tick | driven from the console with `/summon` and `/sable`, never from a player's hand, so no `CraftEventFactory` path was ever entered |

One sentence: **the harness asserted on what the server said, never on what a player does.** Every
one of the tester's findings lives in the gap between those two.

There is a second, structural reason. Folia treats a region tick failure as fatal, so a single bad
cast is a server shutdown. Any test that does not *tick a modded entity in a region with a player
nearby* cannot see the most severe class of failure this build has.

## 3. The extended test complex

Nine suites. Each one names the symptom it would have caught. All are scripted, all run headless on
the box, none require a human.

### T1 — World-state boot (catches §1.1)
Boot against a *copy of a played world*, not an empty one. Assert `Done (`, then assert the enabled
pack list in `level.dat` equals the packs the server actually registered. Run it twice in a row: the
second boot is the one that fails today. Wire the same check into CI with a checked-in world seed
that has Create, Supplementaries and starcatcher data.

### T2 — Mixin manifest (catches §1.4)
Make the error handler write `logs/eturlia-mixins.json`: every mixin config, every target, applied
or skipped, and why. Then assert: zero skipped mixins in any mod that ships worldgen, and a diff
against a checked-in baseline so a new skip fails the run instead of scrolling past.

### T3 — Runtime binding sweep (catches §1.3)
Extend the static scan from "does the class bind" to "is every abstract method of every
CraftBukkit-modified superclass implemented by the mod subclass". `AbstractContainerMenu`,
`CraftEntity`, `Level`, `ChunkGenerator`. Report the exact list; today it prints
`AbstractContainerMenu.getBukkitView()` for every modded menu class in the pack.

### T4 — Entity matrix (catches §1.2, the server-stopper)
For every entity type in the registry that comes from a mod: summon it next to a player-position
marker, let it tick 40 times, and assert no exception reached the region scheduler. Then the same
list again, forcing the CraftBukkit paths: hit a projectile against a block, put a player in a
vehicle, damage a living entity. Assert the Bukkit handle's class is a *specific* Craft class, not
`EturliaUnknownEntity`.

### T5 — Menu matrix (catches §1.3)
For every modded block with a menu and every item that opens one: open it as a real player, assert
the menu id arrives at the client, assert no `AbstractMethodError`, close it. Backpacks, the soul
altar, Create's schematic table, the Vinery barrel.

### T6 — Packet decode harness (catches §1.6, the kick)
Run the modded client headless with `-Dlog4j.configurationFile` capturing netty decode failures, and
a proxy in front of the server that records every clientbound packet. When the client throws
`DecoderException`, dump the last packet: id, entity type, and the data values with their serializer
ids. Compare the server's registry snapshot to the one the client applied. This turns "it kicks me"
into a named registry entry.

### T7 — Worldgen assertions (catches the End and Twilight symptoms)
For each dimension in the pack: generate a fixed radius at a fixed seed, then assert the biome set
is non-empty *and* contains the mod's biomes, and that its structures are placed. `betterend:` in
the End, `twilightforest:` in Twilight. Today the End would fail on biomes and pass on structures.

### T8 — Dimension travel
A real client walks through a Twilight Forest portal, an End portal and a Nether portal. Assert the
client's dimension-change completes and the player ticks in the new world. This is the only way to
see the infinite loading screen.

### T9 — Player soak
A scripted client that places and breaks 200 modded blocks, opens 20 menus, fires 50 projectiles and
relogs 5 times, over 30 minutes, while a second client stands in another region. Assert: server
alive at the end, no region tick failure, no growth in `eturlia-noise.log` classes, no packet
disconnects.

### Cross-cutting changes the suites depend on

1. `logs/eturlia-noise.log` becomes an **asserted artefact**, not a dustbin. Every run ends with a
   grouped diff against a baseline; any new exception class fails the run.
2. The boot grade counts *both* console and noise.
3. `FarCoordGuard` is scoped to the overworld or removed from the rig.
4. Every suite writes a machine-readable verdict file so a run can be judged without reading a log.

## 4. Fixes these findings imply, in order of value

1. **Nearest-vanilla Craft handle for modded entities.** Walk the modded entity's superclass chain
   to the first vanilla class with a Craft implementation and instantiate that, falling back to the
   generic wrapper only for entities that extend `Entity` directly. Removes the server-stopping cast
   and the `CraftLivingEntity → Slime` case at once.
2. **`getBukkitView()` must not be abstract.** Give `AbstractContainerMenu` a default implementation
   that builds a generic `InventoryView` over the menu's slots. Restores every modded GUI.
3. **Datapack resilience.** A missing *generated* pack must be dropped from the world's enabled list
   with a warning instead of aborting the boot.
4. **Mixin manifest** (T2), so silent half-loading stops being invisible.
5. Then the packet work behind §1.6, which T6 is designed to identify.

## 5. What was built and what it found, 2026-08-14

### 5.1 The instrument: `tools/probe/`

A small Bukkit plugin, `EturliaProbe`, built by `tools/buildprobe.sh` against the server that is
actually compiled. It is the thing the old harness never had — it walks the *modded* half of the
registries and reports what the server produces for each entry:

| command | what it does | what it answers |
|---|---|---|
| `eprobe entities` | creates every modded entity type, spawns it at world spawn on the owning region thread, records the class of its Bukkit handle, discards it | which wrapper a modded entity gets, and which types throw before they can be spawned at all |
| `eprobe menus` | builds every modded menu against a real player's inventory and asks it for its `InventoryView` | whether a modded GUI can be opened (needs one player online) |
| `eprobe biomes` | samples a grid in every loaded world and lists the biome keys found | whether a dimension's mod biomes actually generate |

Each writes a TSV under `plugins/EturliaProbe/`, so a run is judged from a file rather than a log.

`tools/menuscan.py` is the static half: it reads the mod jars and the built server jar and reports
every class that inherits a method CraftBukkit added as abstract and never implements it.

### 5.2 Measured before and after

`eprobe entities`, 348 modded entity types in the pack:

| | before | after |
|---|---|---|
| generic `EturliaUnknownEntity` handles | 45 + 159 `CraftLivingEntity` | 45, and only for entities that really do extend `Entity` directly |
| specific vanilla wrappers (`CraftMonster`, `CraftAnimals`, `CraftTameableAnimal`, `CraftWaterMob`, `CraftSlime`, `CraftSpider`, …) | 0 for modded subclasses | 191 |
| types that threw | 8 | 5 |
| region tick failures during the run | — | 0 |

`tools/menuscan.py`, `AbstractContainerMenu`:

```
modded subclasses: 128
without an implementation of their own: 0     (the root now provides one)
```

Those 128 are every backpack, altar, machine and workbench screen in the pack. Each of them threw
`AbstractMethodError` on open before the menu plane, which is why the tester could not open any.

### 5.3 The fixes that produced those numbers

All of them are planes in `scripts/apply_compat_layer.py`, so they regenerate with the build.

1. **Ancestry walk for modded entities.** `CraftEntity.getEntity` now looks up the nearest vanilla
   class in the entity's ancestry and builds that class's Craft wrapper. The index is read from
   `EntityType`'s own fields — their type argument survives in the class file's `Signature`
   attribute, so the vanilla handle class of every registered type is known without touching a
   registry.
2. **A ladder for the vanilla classes no `EntityType` names** — `AbstractHorse`, `AbstractVillager`,
   `AbstractSkeleton`, `Raider`, `TamableAnimal`, `Animal`, `AbstractFish`, `WaterAnimal`,
   `AmbientCreature`, `Monster`, `AgeableMob`, `AbstractMinecart`, `VehicleEntity`, `AbstractArrow`,
   `Mob` — each with its own wrapper. This is what stopped Vinery's mule and Twilight Forest's
   knight phantom from ending the server.
3. **`CraftAbstractVillager.getHandle()` stops casting to `Villager`.** The method is declared to
   return `AbstractVillager`; only the two vanilla subclasses that override it are villagers.
   Supplementaries' red merchant is neither, and the cast threw from inside `AbstractVillager`'s own
   constructor.
4. **`AbstractContainerMenu.getBukkitView()` is no longer abstract.** The default builds a view over
   the menu's own slots: the player is the one whose inventory the menu already carries, the top
   inventory is a live `Container` over every other slot.
5. **`ItemEntity` carries NeoForge's `lifespan` field.** Traveler's Backpack subclasses `ItemEntity`
   and assigns it in its constructor; without the field the subclass threw `NoSuchFieldError` and no
   backpack could be dropped.

### 5.5 The biome census, run the same evening

`eprobe biomes` samples a grid in every loaded world and lists the biome keys it finds. 289 samples
per world, ±512 blocks, spacing 64:

| world | distinct biomes found |
|---|---|
| `world` | `minecraft:plains` — **one** |
| `world_nether` | 9, including `incendium:infernal_dunes`, `incendium:quartz_flats`, `incendium:toxic_heap`, `incendium:weeping_valley` |
| `world_the_end` | `minecraft:the_end` — **one** |
| `world_twilightforest_twilight_forest` | 7, all `twilightforest:` |

`ServerLevel.getBiome` consults the biome source directly when a chunk is not loaded, so this is the
source's own answer, not a sampling artefact — which the Nether and Twilight results confirm.

Confirmed from the console, on a world created with `level-type=minecraft:normal`:

```
minecraft:locate biome minecraft:desert
  Could not find a biome of type "minecraft:desert" within reasonable distance
execute in minecraft:the_end run minecraft:locate biome minecraft:end_highlands
  Could not find a biome of type "minecraft:end_highlands" within reasonable distance
execute in minecraft:the_end run minecraft:locate biome betterend:umbrella_jungle
  Could not find a biome of type "betterend:umbrella_jungle" within reasonable distance
```

A normal overworld with no desert anywhere, and an End with no end_highlands, are not mod problems:
**every world whose biome source comes from a vanilla preset has collapsed to a single biome.** The
two dimensions that work are the two whose source a mod supplies directly. That is why the tester
found structures but no biomes in the End, and it means every worldgen measurement taken on this rig
so far was taken on a world that does not generate.

This is the next round's first item. It is the same neighbourhood as the codec failure in §1.1 - the
overworld preset is a multi-noise source, and `No key preset in MapLike[{biomes:[...]}]` is what the
Nether's source said when it was decoded by the wrong branch - so the two are probably one fault
seen from two sides: one shape of the either-codec throws, the other silently yields nothing and
leaves a fixed biome behind.

`/locate` on this rig needs the `minecraft:` prefix - Essentials owns the unqualified name and
answers with its own usage line. A test that reads the console for `Could not find a biome` has to
send `minecraft:locate` or it will grade an Essentials usage message as a pass.

### 5.4 Still open after this round

- **Five alexsmobs types** (`rocky_roller`, `laviathan`, `giant_squid`, `straddleboard`, `terrapin`)
  throw during construction: they read entity state — `getHealth()`, `isInWaterOrBubble()` — before
  the fields backing it exist. Same class of problem for all five; needs the constructor order
  compared against NeoForge's.
- **The `set_entity_data` decode kick**, the Twilight Forest loading hang and the vanishing block
  placements are all packet-level and still need the client-side harness of §3, T6 and T8.
- **The mixin manifest** (T2) is not built yet, so a mod that half-loads is still only visible as a
  line in `eturlia-noise.log`.
- **`FarCoordGuard`** still clamps in every world; it has to be scoped to the overworld before the
  next live session, or the next tester will fight it again.
