# Code audit — August 2026

Static review of the Eturlia-specific layer (`build-data/`, `neoforge/coremods/`, `compat/`,
`scripts/`, CI, Eturlia patches `0020`–`0083`). Upstream Folia/Paper patches `0001`–`0019`
were not reviewed. Nothing was executed: findings come from reading the code, so items
marked *unverified at runtime* need a real boot to confirm.

**Кратко (RU):** аудит нашёл, что часть «region-aware» слоя не подключена к рантайму, у
coremod'а не совпадал дескриптор метода, событие `ServerStartedEvent` не срабатывало вообще,
лаунчер терял JVM-флаги оператора и не убивал дочерний сервер, а smoke-тест не мог пройти
физически. Всё перечисленное в разделе «Fixed» исправлено, остальное — в «Open».

## Fixed in this pass

### 1. Coremod called a method signature that does not exist
`EturliaFMLBootstrapCoremod.RegionThreadValidator` inserted
`INVOKESTATIC RegionThreadValidatorHooks.checkRegionThread(Lnet/minecraft/server/level/ServerLevel;)V`,
but the hook is declared as `checkRegionThread(Object)` → `(Ljava/lang/Object;)V`.
A matching call site exists: patch `0049` adds `this.tick(shouldKeepTicking)` inside
`ServerLevel.tick(BooleanSupplier, TickRegionData)`. Either the transformer never ran (and
region validation was decorative) or it threw `NoSuchMethodError` on every region tick.
*Fix:* descriptor corrected to `(Ljava/lang/Object;)V`.

### 2. `MinecraftServer.main` rewrite could corrupt the class
The redirector cleared the instruction list but kept `localVariables` / local-variable
annotations, whose labels no longer exist — `MethodNode.accept` can fail when writing the
class. *Fix:* clear label-bearing lists, set `maxStack` / `maxLocals`.

### 3. NeoForge lifecycle events fired in the wrong places (patch `0023`)
- `handleServerStarted()` sat **after** `Thread.sleep(Long.MAX_VALUE)` → `ServerStartedEvent`
  never fired at all. Many mods finish setup and register commands there.
- `handleServerStarting()` sat **inside** `for (;;)` → could fire repeatedly.
- `handleServerAboutToStart()` ran **after** `RegionizedServer.init()` → mod config loading
  happened after region threading had already started.
- `handleServerStopping()` was fired twice (in `stopServer()` and again on the safeShutdown
  path).

*Fix:* AboutToStart → region init → Starting → "Done" → Started, each exactly once; the
duplicate Stopping call removed.

### 4. Launcher dropped the operator's JVM options
The fat jar is a wrapper that spawns a **second** JVM which is the real server. The child
command line was built from scratch, so `java -Xmx16G -jar eturlia.jar` ran the server on the
default heap and every documented `-Deturlia.*` flag (`crash.dir`, `region.guard`,
`thread.validation.*`, `loading.strict`) was silently lost.
*Fix:* the wrapper's own JVM arguments are forwarded to the child (minus the options the
launcher sets itself, and minus agents attached to the wrapper).

### 5. Killing the launcher orphaned the server
No shutdown hook: `systemctl stop`, CI `timeout`, or Ctrl+C on Windows killed the wrapper
while the server JVM kept running — held world lock, occupied port, unsaved chunks.
*Fix:* shutdown hook destroys the child process tree and waits up to 30 s before forcing.

### 6. Library patching required a JDK and re-ran on every boot
`injectClassesFromJar` shelled out to `java.home/bin/jar` (absent on a JRE) and patched
extracted jars in place, which changed their SHA-256 so the launcher re-extracted and
re-patched them on every single start.
*Fix:* rewritten with `java.util.zip` (no external tool), plus a sidecar state file
(`*.eturlia-state`) and an injection marker so the work happens once.

### 7. `client-extra` copy on every boot
Where symlinks are unavailable (Windows without developer mode) the launcher deleted and
re-copied the multi-hundred-megabyte server jar on each start.
*Fix:* reuse an existing up-to-date copy.

### 8. Region guard accepted the threads it was meant to catch
`CrossRegionInvocationGuard.isRegionOrGlobalThread()` accepted any thread whose name
*contains* `"Server"` — Netty IO threads, the console handler, the watchdog. The same
substring test was used in `RegionAwareEventBus`.
*Fix:* real `instanceof` checks against Folia's `RegionizedWorldThread` / `TickThread` via
reflection, falling back to the exact name `"Server thread"` only when Folia classes are
absent.

Also in the guard: the de-duplication set grew without bound (keys embed thread names and
chunk coordinates), and STRICT mode threw only on the *first* occurrence of each key while
silently allowing every repeat. Both fixed (capped set; STRICT always throws).

### 9. `RegionAwareEventBus.dispatchRegion` was missing its thread check
Unlike `dispatchGlobal` / `dispatchEntity` it had no `!isOnRegionThread()` condition, so
every region-scoped event was recorded as a violation and STRICT mode dropped all of them.
*Fix:* condition added; violation bookkeeping bounded and made consistent with STRICT.

### 10. `RegionThreadValidatorHooks` configuration and detection
- Mode flags were resolved in a static initializer, so properties set later (e.g. from
  `config/eturlia.yml`) had no effect → resolved lazily now.
- The thread-name heuristic ran even when the Paper API was available, letting unrelated
  threads pass → heuristic now only used when the API is missing; it also matched `"Tick"`,
  which the javadoc never claimed.
- `ensurePaperApiResolved()` published "resolved" *before* assigning the class, so a racing
  thread silently downgraded to the heuristic → flag now published last.

### 11. Mod compatibility manifest was never actually parsed
`EturliaModLoadingPlugin` ignored `eturlia-supported.json` entirely: `parseModEntries`
returned four hard-coded ids and `parseExcludedMods` returned a single entry with all fields
`null`, so the documented hard block on `c2me` could never match. The resource path also
disagreed with the build, which packages the file under `META-INF/`.
*Fix:* real (dependency-free) JSON reader, both resource paths tried, malformed manifests
degrade to permissive mode with a clear log line.
*Note:* this plugin still has no SPI registration — see "Open" below.

### 12. Mixin configs that could only crash
`eturlia-core.mixins.json` declared `"required": true`, a mixin plugin class that does not
exist, and four "mixins" that were empty stub classes without `@Mixin`. The two compat
modules did the same with six/four non-existent classes.
*Fix:* dead configs and stub classes removed; compat modules no longer declare a `[[mixins]]`
config, so installing them no-ops instead of failing mod loading.

### 13. Compat modules could not resolve their dependencies
`compileOnly("com.simibubi.create:Create:0.5.1.f")` from `maven.creativetab.dev` — wrong
coordinates (an MC 1.18/1.20 build) from a repository that never hosted Create; same for
Create Big Cannons, Sable and Create Aeronautics.
*Fix:* unresolvable coordinates commented out with the correct repository noted; both modules
documented as skeletons in `compat/README.md` and in their mod descriptions.

### 14. Smoke test could not pass
`scripts/smoke-test.sh` never changed into the server directory, so `eula.txt` was written
where the server never looked (it exits immediately without an accepted EULA) and the crash
report / log checks pointed at an empty directory. Shutdown was implemented by launching a
**second** server against the same directory, and `kill -9` hit only the wrapper.
*Fix:* server runs in its own directory, EULA written there, SIGTERM to the wrapper (whose
new shutdown hook stops the child), leftovers force-killed.

### 15. Sync script hard-coded another machine's paths
`scripts/sync-patches-to-server.py` used `/home/z/my-project/...`. *Fix:* paths resolved from
the repository root, with `--features` / `--server` / `--dry-run` options.

### 16. Config handling
- `applyToPaperGlobal` caught only `ReflectiveOperationException`; Paper field type/visibility
  drift raises `IllegalArgumentException`, which escaped and aborted config loading.
- `_version` was read but never compared → no warning when the on-disk config predates the
  build (new keys are never merged into an existing file).
- The built-in YAML subset silently mis-parsed tab indentation and sequences.
- Documented keys that no code read: `lod.max-render-distance`, `lod.dh-server-component`,
  `lod.voxy-support` (now propagated to `ClientLodConfig`), `mods.require-lithostitched-min`
  and `mods.block-lithostitched-prerelease` (now honoured by `LithostitchedCompatGate`
  instead of its hard-coded constant). Remaining informational keys are marked as such.

### 17. Smaller items
- `preferNewestLib` compared jar names lexicographically: `commons-lang-2.6` outranked
  `2.10`. Now compares numeric version segments.
- `eula.txt` was generated without the EULA URL; the standard comment header is back.
- Startup banner spelled `CONTED` (a leftover from an earlier project name).
- `EturliaServer.main` now refuses re-entry instead of recursing if the coremod redirect and
  `runServer()` ever point at each other.
- Leaked `InputStream` in `resolveEturliaVersion`, deprecated `Thread#getId`, dead private
  method `injectClassesFromFolia`.
- CI: added `permissions: contents: read`, a `concurrency` group, Gradle caching, log upload,
  and a smoke step that actually kills the child JVM (`timeout` only signalled the wrapper).
- Docs: patch range in the README said `0020`–`0038` (the tree has `0020`–`0083`); the shim
  description contradicted `build.gradle.kts`; `PROJECT_DESCRIPTION.md` was an upstream Folia
  redirect that said nothing about this fork; one Russian line was left in the English
  section.

## Second pass — v0.2.5 (patches through 0094)

Re-audit after the ASIC bridge wave. The findings above were all still present; these are
new, introduced by patches `0084`–`0094` and the `mods/` hygiene pass.

### 18. `TemptGoal` cast crashed on any non-player target (patch `0085`)

`TemptGoal.player` was narrowed from `LivingEntity` to `Player` for a Farm & Charm accessor,
with a hard cast on the Bukkit event result:

```java
this.player = (event.getTarget() == null) ? null : (Player) ((CraftLivingEntity) event.getTarget()).getHandle();
```

`EntityTargetLivingEntityEvent` lets a plugin set *any* `LivingEntity` as the target, so
`event.setTarget(someZombie)` threw `ClassCastException` inside AI ticking on a region thread.
*Fix:* `instanceof` pattern — a non-player target now simply means "not tempted".

### 19. The `dropAllDeathLoot` bridge was never invoked (patch `0084`)

The patch added a vanilla-shaped `void dropAllDeathLoot(ServerLevel, DamageSource)` "for Let's
Do / Farm & Charm mixins" and renamed every internal call site to `paperDropAllDeathLoot`
(`LivingEntity.die`, `Fox`, `ArmorStand`). Nothing in the server called the void method, so
mods injecting into it never ran — the bridge existed only on paper.
*Fix:* the void method is now an explicit anchor that `paperDropAllDeathLoot` invokes, the same
shape patch `0049` uses for `ServerLevel.tick`.

### 20. `Main.main(String[])` could re-enter the whole boot (patch `0094`)

The restored Mojang-shaped entry point is `public`, ignores its `String[]` argument entirely and
reads the `OptionSet` from a `ThreadLocal`. A mod calling `Main.main(args)` on the boot thread
re-ran the entire server startup body against the same world.
*Fix:* one-shot `AtomicBoolean` guard; a second entry fails loudly instead of double-booting.

### 21. `mods/` hygiene mutated the operator's directory with no opt-out

`EturliaModsFolderHygiene` renames `spark-*neoforge*` and the original `arclight_sable_patch`
to `*.jar.eturlia-skipped` on every boot. There was no property to disable it, renaming a file
back just got it renamed again next start with no hint that this would happen, and
`Files.move(..., REPLACE_EXISTING)` silently discarded an existing soft-skip of the same name.
*Fix:* `-Deturlia.mods.hygiene=skip|warn|off` (default `skip`), no clobbering of an existing
soft-skip, and the log line now explains how to stop the behaviour.
`EturliaServerLaunchHandler.resolveGameDir()` also caught only `ReflectiveOperationException`,
so a `ClassCastException` from the `FMLPaths.GAMEDIR` lookup would abort mod-file discovery.

### 22. `Item.Properties.setNoRepair()` is a no-op (patch `0085`)

It sets a private `canRepair` field that nothing reads, so items stay repairable. Not silently
"fixed" here — anvil behaviour is a design decision — but the field now has an accessor and a
comment saying it is not enforced, instead of looking like a working API.

## Open — not fixed here

1. **`eturlia.EturliaServer` is not on the boot path.** `EturliaServerLaunchHandler.runService`
   calls `org.bukkit.craftbukkit.Main` directly, and the coremod redirect targets
   `MinecraftServer.main`, which does not exist in the patched tree. Consequence: the crash
   handler, `eturlia-crash-reports/` and `RegionAwareEventBus` never initialise, although the
   README advertises them. Deciding *where* they should be installed is a design call.
2. **`EturliaModLoadingPlugin` has no SPI registration.** Nothing calls `onLoad`, so the
   supported/excluded manifest is still inert even now that it parses correctly.
3. **`ServerTickEvent` / `LevelTickEvent` fire per region tick.** Gating them to a single
   global tick needs a Folia API decision; documented as a known limitation for now.
4. **`ClientLodConfig` (≈35 KB) is unreachable code** — nothing constructs it.
5. **Sable anchor patches (`0044`–`0063`)** pin lambda names and method descriptors
   (`lambda$stopSleeping$12`, `ChunkMap.unloadQueue`, …) to one third-party mod's refmap.
   Any upstream reorder breaks them silently. Worse, `ServerLevel.tick(BooleanSupplier)` from
   patch `0049` has an **empty body**, so a mod injecting anywhere other than `HEAD` gets a
   call with none of the tick's state.
6. **`ArgumentTypeInfos.BY_CLASS` (patch `0027`)** is a plain `HashMap` with a `synchronized`
   writer and unsynchronized readers.
7. **Directory case collision.** `settings.gradle.kts` points `:folia-server` at `Folia-Server`
   while the repository tracks `folia-server/`. These are the same directory on Windows/macOS
   and different ones on Linux; `.gitignore` only lists the capitalised generated paths.
8. **Vendored binaries without provenance** — `build-data/*/libs/*.jar` and
   `compat/shims/arclight_sable_patch-1.1.1-eturlia-shim.jar` are committed with no checksum
   or source reference.
9. **`MISSING_PATCHES_ANALYSIS.md`** still states that the NeoForge `minecraft-patches` are
   absent from version control.

### From the second pass

10. **`EntityRemoveEvent` loses its cause.** Patches `0084`/`0085` replaced
    `discard(EntityRemoveEvent.Cause.DESPAWN)` in `Mob.checkDespawn` (three sites) and
    `discard(Cause.DROP)` in `LeashFenceKnotEntity` with the no-arg `discard()`, so that
    letmedespawn/horseman can target `discard()V`. Plugins now see `Cause.DISCARD` for every
    despawn. Restoring the cause would break those mixin anchors, so this needs a maintainer
    decision — e.g. keep the no-arg call site but have `Entity.discard()` consult a pending
    cause set by the caller.
11. **The level-constructor `ThreadLocal` can leak a world's Bukkit extras** (patch `0091`).
    `Level.ETURLIA$LEVEL_CTOR_EXTRAS` carries `ChunkGenerator` / `BiomeProvider` /
    `World.Environment`; it is set at the call site and removed only on the success path at the
    end of the `ServerLevel` constructor. If construction throws — most plausibly in
    `CraftServer.createWorld`, after which the server keeps running — the value stays bound to
    the thread, and `eturliaResolveCtorExtras` unconditionally reuses a non-null value. The next
    world (or a Moonlight `FakeServerLevel`) would silently inherit another world's generator and
    environment. The fix is `try`/`finally` at the three call sites, or storing the extras in a
    `Level` field and clearing the `ThreadLocal` immediately after `super()`; both require
    re-cutting hunks across patches `0048`/`0090`/`0091`, which cannot be validated without a
    full `applyPatches` run — left to the maintainer rather than guessed at.
12. **`IExtensibleEnum` is declared but not implemented** (patch `0084`). `DamageEffects`,
    `Boat.Type`, `ItemDisplayContext` and `BiomeSpecialEffects.GrassColorModifier` all return
    `ExtensionInfo.nonExtended(...)`, so a mod adding entries through NeoForge enum extension
    gets nothing — and finds out only when the content is missing at runtime.
13. **Hand-written methods named after synthetic lambdas** (patches `0036`, `0042`, `0046`):
    `lambda$reloadResources$29`, `lambda$forStructuresInChunk$2`, `lambda$stopSleeping$12`. They
    satisfy third-party refmaps, but any edit that changes lambda numbering in those classes can
    collide with a genuinely generated name and fail compilation.
